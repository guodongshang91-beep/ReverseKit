# FAQ

## 通用

**Q：这跟 nuclei / subfinder / httpx 是什么关系？**

能力上有重叠，定位不同。项目 discovery 那套工具是通用扫描器，覆盖面广；
ReverseKit 的重点是**判定质量**和**链路可复现**——它的五道假阳性防线是
通用工具里没有的，因为通用工具默认不替你判断"这个 200 是不是兜底页"。

在大陆网络环境下还有现实原因：GitHub Releases 直连经常 `000`，镜像返回的是
HTML 而不是 zip 包。所以核心链路刻意做成了**纯标准库 + requests**，
不需要拉二进制。

**Q：为什么脚本之间代码有重复？**

刻意的。每个脚本都能单独下载就跑，不装包、不改 import 路径。
代价是少量重复（UA 常量、`hx()` 之类），收益是任何一个脚本坏了不影响其他。

**Q：能只用其中一个模块吗？**

可以。模块之间只通过 JSON 文件解耦，没有代码依赖。
只想做 DNS 侦察就只用 `dnsx.py`，它零依赖。

## web-recon / src-hunt

**Q：为什么我的扫描结果全是 200？**

站点是 catch-all（SPA 兜底路由 / WAF 兜底页 / 统一错误页）。
先跑基线：`GET /<random>-probe`，如果它也返回 200，那这个站上所有 200 都要跟基线比长度和 md5。
详见 [04-false-positive.md](04-false-positive.md)。

**Q：`unauth_scan` 命中 40 条，怎么快速筛？**

按 md5 分组。同一 md5 出现 3 次以上的整组丢掉（兜底页）。
剩下的逐条看正文前 400 字节——如果正文里出现的就是你请求的路径，那是 404 回显，也是假的。

**Q：子域枚举拿不到量怎么办？**

三个来源都试：crt.sh（证书透明）、被动 DNS 源、前缀爆破。
爆破字典按目标行业改——通用字典在大厂上基本无效，因为子域命名是业务驱动的
（`wms` `rcmp` `dlp` `boss` `bi` 这类）。

**Q：能扫 gov / edu 吗？**

多数 SRC 平台对 gov/edu 有单独的权重和提交要求，且往往需要额外授权。
除非你确认自己在授权范围内，否则别碰。

**Q：扫出来的 IP 资产能报吗？**

多数平台"IP 漏洞暂不收取"。必须用「该厂商自有域名下的前端 JS 引用了该地址」
把它与厂商绑定，否则会被当无主资产忽略。

## binary-re / pe-patch

**Q：`xref` 在 ARM64 上一个都搜不到？**

正常——ARM64 位置无关代码不写完整地址字面量，走 `adrp` + `add`。
`elfkit xref` 已经实现了这对指令的解码；如果仍然 0 命中，
那可能是这个字符串只被**重定位**引用（`.rela.dyn`），不在 `.text` 里直接引用。

**Q：`dis` 报 `capstone required`？**

```bash
pip install capstone
```

**Q：补丁后程序起不来 / 闪退？**

三种常见原因：
1. 目标有 CFG（控制流保护），把中间指令改成 `jmp` 会触发异常 → 改条件跳转或整块 `nop`；
2. 有完整性自检（CRC / 签名）→ 先找校验函数；
3. 补丁破坏了指令对齐或后续指令的立即数 → 重新反汇编确认边界。

**Q：为什么不直接上 IDA / Ghidra？**

该用的时候要用。这套脚本解决的是「没有 IDA」「目标有反调试不敢动态调」
「需要可复现、可交接的批处理」这三类场景。
Ghidra 能跑的场合，用它看伪代码更快。

## wifi

**Q：抓不到握手？**

按顺序检查：
1. Npcap 装了吗，`wpcap.dll` 在不在；
2. 用来连的配置文件是不是**密码错误**的（密码对了就不会有失败的 M2）；
3. 是否开了 802.11w（PMF）——开了的话四次握手不完整；
4. `netsh wlan show interfaces` 有没有出现"正在验证"状态。

**Q：`analyze.py` 报 `no handshake found`？**

pcap 里可能只有 M1。检查过滤条件（EAPOL ethertype `0x888e`）和是否有 M2 的 MIC 字段。

**Q：为什么先跑 `--self-test`？**

用已知密码的合成握手验证 PBKDF2 → PMK → PTK → MIC 全链路。
不然"抓包失败"和"算法写错"混在一起，很难排。

## android

**Q：免 root 真的只有两条路？**

要求"不 root"且目标是**别的应用**，只有 `AccessibilityService.dispatchGesture()`
或 USB HID（外接硬件）。要 root / 内核权限的还有四条（见模块 README）。
如果你只是想自动化**自己的应用**，直接在应用内注入事件即可，不需要这些。

**Q：手工构建 APK 为什么不用 Gradle？**

Gradle 在老机器 / 沙箱里经常死在 native 服务初始化（`native-platform.dll` 加载失败）。
手工链路更啰嗦但完全可控：`aapt2 → javac → d8 → zipalign → apksigner`。

**Q：改完 `.so` 装不上？**

必须重新签名。`INSTALL_FAILED_INVALID_APK` 基本都是签名或对齐问题。

## 贡献

**Q：我能加自己的扫描规则吗？**

可以，但**必须同时给出对应的假阳性防线**。只加正则不加防线的 PR 会被要求补充。

**Q：能提交我挖到的漏洞样本吗？**

不要。仓库里不放真实目标、真实数据、真实凭据。用占位域名和合成样本。
